## Brand voice — apply to all customer-facing copy

This applies to anything visible on the storefront: page titles, meta descriptions, alt text, headings, button labels, error/empty states, marketing copy.

**Rules (non-negotiable):**

- Declarative. Statements only.
- Present tense.
- No exclamation marks.
- No questions in marketing copy.
- No promotional/salesy CTAs ("Buy now!", "Limited time!", "Don't miss out!").
- Minimal, cinematic, confident.
- Sign personal/editorial pieces with `—Fred`.

**Recurring brand phrases (use when natural, never force):**

- "No Apologies"
- "Made for those who already know"
- "The Culture Doesn't Wait"
- "Wear it like a decision"
- "Refined in Paris. Born Everywhere"
- "Paris doesn't follow anyone"

**Brand identity:**

- Audience: 16–35
- References: Saint Laurent, Fear of God, Vogue editorial
- Colors: Absolute Black `#0A0A0A`, FredJo Gold `#B8975A`, Ivory `#F5F4F0`, Gold-light `#D4B67A`, Red-muted `#8A4A4A`
- Typography (storefront): Bebas Neue (display), Cormorant Garamond (editorial italic), Montserrat (body), JetBrains Mono (technical/data)

## Codebase rules — non-negotiable

These are hard constraints. Breaking them costs Fred real time.

### 1. Never modify `config/settings_data.json`

This file is owned by the Shopify theme editor. Any change pushed via Git will be overwritten by Shopify on the next merchant save, or worse — will create a sync conflict. If a setting needs to change, change `config/settings_schema.json` (the schema definition) and let the merchant edit the value in the admin.

### 2. Never rename `schema.name` in section schemas

The `name` field in a section's `{% schema %}` block is the human-readable label in the theme editor. Renaming it can detach the section from existing pages that reference it by name. Add new translations or update `t:` keys instead.

### 3. Preserve all `{% schema %}` block IDs

Block IDs are referenced in `settings_data.json` to position content. Renaming or removing a block ID erases merchant-configured content silently.

### 4. Liquid: `{%- -%}` whitespace control

Impulse 8.0 uses tight whitespace control. Match the existing style — `{%-` and `-%}` to suppress whitespace, `{% %}` when whitespace is intentional. Don't introduce trailing newlines in inline contexts.

### 5. Translations live in `locales/`

Hardcoded strings in templates/sections are forbidden for customer-facing copy. Use `{{ 'key.path' | t }}` and add the key to `locales/fr.json` (primary) and `locales/en.json`. The store is bilingual FR/EN; FR is the canonical voice.

### 6. CSS: scoped to component files

Impulse 8.0 has component-scoped CSS in `assets/`. Don't add global styles unless extending an existing global file. Match the existing naming convention — typically `theme.css`, `section-{name}.css`, `component-{name}.css`.

### 7. JS: defer and progressive enhancement

Impulse 8.0 ships with `defer` on all theme JS. Don't add blocking scripts. Don't introduce jQuery — the theme is vanilla JS. Don't introduce a build step.

### 8. Image assets

New images go in `assets/`. Reference via `{{ 'filename.webp' | asset_url }}`. Prefer WebP. Always include `width`, `height`, and meaningful `alt` text (see brand voice for alt text style — declarative, descriptive, not keyword-stuffed).

### 9. Performance budget

Impulse 8.0 is already heavy. Don't add new third-party scripts without justifying the perf cost. Lighthouse mobile score should not drop below 60 on the homepage post-change.

### 10. SEO files

- `sitemap.xml` is auto-generated by Shopify. Don't override.
- `robots.txt` can be customized via `templates/robots.txt.liquid`. Edits here ship to production immediately.
- Meta tags are set in `snippets/meta-tags.liquid`. Schema.org JSON-LD lives in dedicated snippets — typically `snippets/schema-product.liquid`, `snippets/schema-organization.liquid`.

## File structure (Impulse 8.0)

```
assets/           — CSS, JS, images, fonts
config/           — settings_schema.json (editable), settings_data.json (DO NOT EDIT)
layout/           — theme.liquid (master), checkout.liquid, password.liquid
locales/          — fr.json (canonical), en.json
sections/         — modular page sections
snippets/         — reusable partials (meta-tags, schema-*, etc.)
templates/        — page templates (product, collection, cart, etc.)
templates/customers/  — account-related templates
```

**SEO-relevant files:**

- `snippets/meta-tags.liquid` — title tag, meta description logic
- `snippets/schema-product.liquid` — Product schema.org JSON-LD
- `snippets/schema-organization.liquid` — Organization schema.org JSON-LD
- `templates/robots.txt.liquid` — robots.txt customization
- `sections/header.liquid` — nav structure (capitalization issues fixed in admin, not code)

## Fred's working style

- **Single-word confirmations advance work.** "yes" / "yes just do it" = proceed. No need to re-confirm.
- **Terse responses preferred.** No trailing summaries of what was just done — the diff speaks for itself.
- **Show, then ship.** For non-trivial changes, show the diff before push. Once a pattern is established, batch-execute is fine.
- **Real data over aspirational estimates.** Don't pad numbers. If something is unknown, say so.
- **No promotional language in commit messages either.** Conventional commits: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `perf:`, `style:`. Lowercase. Imperative mood. Concise.
- **Pause after each commit during Phase 1 ramp-up.** First 3–4 commits, wait for Fred's "yes" before pushing the next task.

## Git conventions

**Commit message format:**

```
type(scope): brief imperative description

Optional body explaining why, not what.
```

**Examples:**

- `fix(seo): set canonical URL on collection pages`
- `feat(meta): add Product schema.org JSON-LD`
- `chore(robots): exclude /search from crawl`
- `style(footer): align copy with brand voice (no exclamation)`

**Branching:**

- Direct commits to `main` for Phase 1 SEO tasks (low risk, reversible, Fred validates each one).
- For larger refactors or multi-day work, branch from `main` (`feat/xxx`), push the branch, connect it as a Shopify preview theme, validate, then merge.

## Tasks Claude Code does NOT execute

These are admin actions that require Shopify Admin or Google Search Console access — not codebase edits. Claude Code skips them and notes them in the commit log or in `PHASE-1-EXECUTION.md` as `Type: admin`.

- Navigation menu capitalization (Shopify Admin → Online Store → Navigation)
- 301 redirects (Shopify Admin → Online Store → Navigation → URL Redirects)
- Google Search Console verification, sitemap submission, indexing requests
- Shopify metafield value edits (Admin → Settings → Custom data)
- Theme settings changes (Admin → Online Store → Themes → Customize)
- Email/Klaviyo template edits
